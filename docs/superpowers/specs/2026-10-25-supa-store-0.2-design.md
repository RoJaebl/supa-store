## 1. 의도

editor 의 화면 앱은 서버 조회를 React Query 로 하고 있고, 이것을 supa-store 로 옮기기로 했다. editor 가 쓰는 React Query 기능
가운데 supa-store 0.1.0 의 `createResource` 로 나타낼 수 없는 것이 있다. 이 판은 그 빈자리를 채운다.

**기준은 supa-store 의 설계다.** store key · `createResource` · `args` · `Cache` · event · `useStore` 옵션이라는 지금의 틀에
React Query 의 기능 하나하나를 대어 보고, 그 틀로 나타낼 수 없는 것만 더한다. editor 의 코드는 이 판의 결과에 맞춰 다시 짠다.
한 저장소의 사정(「같은 저장소일 때만」 같은 규칙)은 더할 이유가 되지 않는다.

## 2. 목표

1. `useStore(key, { args: [a, b, …] })` 로 같은 자원의 여러 `args` 를 한 번에 꺼낸다. `Cache` 도 `args` 배열을 받는다.
2. 화면에서 바꾸기를 `mutateAsync` 로 부르면 결과를 돌려받고 실패를 `catch` 로 받는다. 칸(`pending` · `data` · `error`)은
   `mutate` 와 똑같이 고쳐진다.
3. 자원 또는 화면이 정한 간격으로, 그 `args` 를 보는 화면이 있는 동안 주기적으로 다시 받는다.
4. `args` 가 바뀌어 새 값을 받는 동안과 그것이 실패한 뒤에도, 자리를 채운 값(지어낸 값 또는 앞 값)을 보인다.
5. 화면에 줄 때 값을 바꾸어 주고, 바꾼 결과가 바로 전과 같으면 다시 그리지 않는다.
6. 자원의 `pick` 이 보통 store 의 `pick` 처럼 고른 칸이 바뀔 때만 다시 그린다(0.1.0 의 결함 고치기).
7. 이 판에서 더하는 것을 지금의 정의는 그대로 쓴다. `createResource` 의 정의 함수와 `query` 서명은 바뀌지 않는다.

## 3. 하지 않는 것

- **바깥 연결(웹소켓 · SSE · 프로세스)의 생명주기.** `createStream` 과 서버 도우미는 0.3 이 맡는다(§13).
- **React Query 의 기능을 이름 그대로 모두 옮기기.** 지금 틀로 나타낼 수 있는 것은 쓰는 법만 README 에 적는다(§7).
- **store 끼리의 구독.** `ctx` 는 지금처럼 부르는 순간의 값만 준다. store 사이의 바뀜은 event 가 잇는다.
  - 0.5 에서 바뀜 — `select` 안에서 읽은 바꾸기 상태만은 따라간다. 2026-10-30 설계(`2026-10-30-supa-store-mutation-state-design.md`) 참조.
- **깊이 견주기.** 다시 그릴지 가를 때 겉 한 겹만 견준다(§12).
- **캐시 지우기(React Query 의 `gcTime`).** 받아 둔 값은 지금처럼 앱이 도는 동안 남는다.

## 4. 실패로 보는 것

- 0.1.0 으로 지은 정의 파일을 고쳐야 0.2 를 쓸 수 있다. 바뀌어도 되는 것은 화면 코드의 `mutate` 결과 받기뿐이다(§14).
- 같은 `args` 를 여러 화면이 보는데 타이머가 화면 수만큼 돈다.
- 목록에 항목이 끼어들거나 빠질 때 자리를 채운 값이 옆 항목의 것으로 밀린다.
- `select` 나 `pick` 을 주었는데, 고르지 않은 칸이나 바꾼 결과에 영향이 없는 바뀜으로 다시 그린다.
- 늦게 온 응답이 더 나중 요청의 결과를 덮는다(0.1.0 이 막던 것을 새 기능이 깬다).
- 제품 빌드에서 타이머나 구독이 화면이 떠난 뒤에도 남는다.

## 5. 고려한 길

### 5.1 React Query 의 기능을 어디까지 supa-store 에 넣는가

| 길 | 무엇을 하는가 | 맞바꾸는 것 |
|---|---|---|
| 정식 옵션으로 모두 갖춘다 | React Query 의 옵션마다 대응하는 옵션을 둔다 | 옮기기는 기계적이지만, 1곳에서만 쓰는 것도 공개 API 가 되고 한번 내면 거두기 어렵다 |
| **지금 틀로 나타낼 수 없는 것만 더한다(고른 길)** | 지금 `Cache` 와 바꾸기 함수로 되는 것은 쓰는 법만 적는다 | 새 API 가 좁다. 쓰는 쪽이 몇 꼴을 직접 짓는다 |

사람이 둘째 길을 골랐다. 공개 패키지의 표면을 좁게 지키고, 손으로 짓는 꼴이 여러 곳에서 되풀이되면 그때 옵션으로 올린다.

### 5.2 바깥 엔진을 이 판에 넣는가

처음 물음은 「`createStore` 가 바깥 엔진의 `subscribe` 를 감싸는가」였다. 설계를 이어 가니 클라이언트 도우미 · 연결의 약속 ·
웹소켓과 SSE 서버 도우미까지 커졌다. 나머지 다섯 기능은 모두 `createResource` · `useStore` 안의 일이고 editor 의 이관이
그것을 기다린다. 사람이 둘을 판으로 나누기로 했다. 이 판은 다섯 기능과 `pick` 고치기만 담는다.

## 6. 기능 하나하나를 지금 틀에 대어 본 결과

| React Query 기능 | supa-store 에서 그것을 나타내는 자리 | 이 판에서 하는 일 |
|---|---|---|
| `setQueryData` · `getQueryData` | 자원의 `Cache` 인 `getData(args)` · `setData(updater, args)` | 쓰는 법만 적는다(§7) |
| `onMutate` 낙관적 갱신 | 바꾸기 함수 안에서 `getData` 로 앞 값을 쥐고, 실패하면 `setData` 로 되돌린다 | 쓰는 법만 적는다 |
| `useInfiniteQuery` | 바꾸기 함수가 다음 쪽을 받아 `setData` 로 이어 붙인다 | 쓰는 법만 적는다 |
| `invalidateQueries` | 자원의 `invalidate(args)` 와 event 의 `on` | 쓰는 법만 적는다 |
| `useQueries` | `useStore` 는 `args` 하나만 받는다 | `args` 배열을 받는다(§8) |
| `mutateAsync` | 화면의 `mutate` 는 실패를 칸에만 둔다 | `mutateAsync` 를 더한다(§9) |
| `refetchInterval` | 시간에 따라 다시 받는 자리가 없다 | 옵션을 더한다(§10) |
| `placeholderData` · `keepPreviousData` | 같은 `args` 안에서만 앞 값을 남긴다 | 옵션과 도우미를 더한다(§11) |
| `select` | `pick` 은 칸만 고른다 | 옵션을 더한다(§12) |

## 7. 쓰는 법만 적는 것

README 에 「React Query 에서 옮겨 올 때」 절을 두고 아래 꼴을 적는다.

```ts
// 캐시를 직접 읽고 쓴다 — store 안에서는 ctx, 밖에서는 getStore
ctx("api.settings").getData();
ctx("api.settings").setData((prev) => ({ ...prev!, theme: "dark" }));

// 낙관적 갱신 — 바꾸기 함수 안에서. 늦게 온 조회 응답은 setData 가 올린 차례가 이미 버린다
createResource((cache: Cache<void, Settings>) => ({
  query: fetchSettings,
  async save(patch: Partial<Settings>) {
    const prev = cache.getData();
    cache.setData((s) => ({ ...s!, ...patch }));
    try {
      const saved = await putSettings(patch);
      cache.setData(saved);
      return saved;
    } catch (e) {
      cache.setData(prev);
      throw e;
    }
  },
}));

// 쪽 단위로 이어 받기 — data 를 쪽 배열로 두고 바꾸기가 다음 쪽을 이어 붙인다
createResource((cache: Cache<{ sessionId: string }, Page[]>) => ({
  query: async ({ sessionId }) => [await fetchPage(sessionId, null)],
  async loadMore(sessionId: string) {
    const pages = cache.getData({ sessionId }) ?? [];
    const next = await fetchPage(sessionId, pages.at(-1)?.cursor ?? null);
    cache.setData([...pages, next], { sessionId });
  },
}));

// 다른 자원이 바뀌면 낡게 한다 — event 를 듣는다
createStore("api.graph", (set, get, ctx) => {
  const graph = createResource(() => ({ query: fetchGraph }));
  ctx("event.repo.changed").on(ctx.key, () => void graph.invalidate());
  return graph;
});
```

## 8. 여러 `args` 를 한 번에 — `useQueries` 의 자리

### 8.1 부르는 꼴

```ts
useStore("api.file.dirLevel", { args: { repo, dir } });                               // 하나 — 0.1.0 그대로
useStore("api.file.dirLevel", { args: openDirs.map((dir) => ({ repo, dir })) });      // 목록
useStore("api.file.dirLevel", { args: [...], pick: ["data", "status"] });              // 목록 + pick
```

- `args` 자리에 값 하나를 주면 하나, 배열을 주면 목록이다. 돌려주는 것은 목록이면 같은 순서의 배열이다.
- store 는 여전히 key 하나다. 목록으로 꺼낸 화면과 하나로 꺼낸 화면이 같은 값을 나눠 갖는다.
- 목록의 `pick` · `omit` 은 조회 칸(`data` · `status` · `error` · `isPlaceholderData` · `refetch`)만 고른다. 바꾸기 칸은 자원 전체에
  하나라 목록의 항목에 넣지 않는다. 바꾸기는 `useStore(key)` 나 하나 꼴로 꺼낸다. 타입도 목록이면 `pick` 에 바꾸기 이름을 적지
  못하게 좁힌다.
- 목록 길이가 바뀌어도 훅의 수는 같다. 하나 꼴과 목록 꼴이 같은 훅을 같은 차례로 부르므로, 한 자리에서 렌더마다 둘을 오가도
  훅 순서가 바뀌지 않는다.
- 받기는 `args` 마다 0.1.0 과 같다. 아직 받지 않은 것은 받고, 받은 것은 캐시에서 주고, 받는 중인 것은 요청을 나눠 쓴다.

### 8.2 `Cache` 도 같은 규칙

```ts
levels.getData({ repo, dir });                       // D | undefined
levels.getData([{ repo, dir: "" }, { repo, dir }]);  // (D | undefined)[]
levels.invalidate([a, b]);                           // a 와 b 만 다시 받는다
levels.invalidate();                                 // 받아 둔 것 모두 — 0.1.0 그대로
levels.invalidate([]);                               // 아무것도 하지 않는다
await levels.fetch([a, b]);                          // D[] — 하나라도 실패하면 그 오류로 거절한다
levels.setData((prev, args) => …, [a, b]);           // args 마다 updater 를 부른다
```

### 8.3 생성기 검사: `args` 를 배열로 짓지 않는다

맨 배열을 언제나 「목록」으로 읽으려면 `args` 자체가 배열인 자원이 없어야 한다. 있으면 `getData([1, 10])` 이 범위 하나인지
값 둘인지 런타임이 가를 수 없다. 그래서 생성기가 정의를 읽을 때 `query` 의 인자 타입이 배열 또는 튜플이면 실패한다.

```
src/range.state.ts: 자원의 args 는 배열로 짓지 않는다 — 여러 값은 객체로 묶는다
```

0.1.0 의 「key 는 문자열 그대로 쓴다」 검사와 같은 자리(`tools/codegen.cjs`)에 둔다.

## 9. 던지는 바꾸기 — `mutateAsync`

```ts
export interface MutationView<F extends Fn> {
  /** 결과와 실패를 칸에 둔다. 부른 자리에는 아무것도 주지 않는다 */
  mutate(...args: Parameters<F>): void;
  /** mutate 처럼 칸에 두고, 결과를 부른 자리에도 돌려준다. 실패하면 원래 오류 객체를 던진다 */
  mutateAsync(...args: Parameters<F>): Promise<Awaited<ReturnType<F>>>;
  pending: boolean;
  error: string | null;
  data: Awaited<ReturnType<F>> | undefined;
  reset(): void;
}
```

- 두 함수는 칸을 똑같이 고친다. 부르면 `pending` 이 `true`, 성공하면 `data` 에 결과, 실패하면 `error` 에 문구.
- 칸이 기계적으로 처리하는 몫은 늘 같고, 그것으로 모자란 처리(창 닫기 · 토스트 · 다음 요청 잇기)만 `mutateAsync` 를 부른
  자리가 덧붙인다.
- `error` 칸은 화면에 보일 문구(`string`)이고, `mutateAsync` 가 던지는 것은 원래 오류 객체다.
- 같은 화면에서 뒤 요청이 앞 요청을 넘어서면 앞 요청의 응답은 칸을 덮지 못한다(0.1.0 그대로). 그래도 `mutateAsync` 는 그 앞
  호출의 결과나 실패를 자기를 부른 자리에 돌려준다.
- store 끼리 · 시험은 지금처럼 `ctx(key).save(…)` 로 함수를 바로 부르고, 실패는 그대로 던져진다. `mutate` · `mutateAsync` 는
  화면이 `useStore` 로 꺼낼 때만 생긴다.
  - 0.5 에서 바뀜 — `mutate` · `mutateAsync` 는 여전히 화면에서만 생기지만 바꾸기 상태(`inflight` · `pending` · `error` · `data`)는 자원이 쥐어 store 에서도 읽힌다. 2026-10-30 설계 참조.

## 10. 주기적으로 다시 받기 — `refetchInterval`

### 10.1 꼴과 자리

```ts
type RefetchInterval<A> = number | false | ((args: A) => number | false | undefined);

createResource(define, { refetchInterval?: RefetchInterval<A> });
useStore(key, { args, refetchInterval?: RefetchInterval<A> });   // args 는 하나 또는 배열
```

### 10.2 간격을 정하는 차례 — `args` 하나마다

1. 자원의 값을 그 `args` 로 구한다. 숫자면 그것을 쓴다. **이때 화면의 값은 보지 않는다** — 자원이 60초로 정하면 화면이
   5초를 주어도 60초다(사람이 정했다). 화면의 값은 자원이 정하지 않은 `args` 를 채우는 몫이다.
2. `false` 나 `undefined` 면, 그 `args` 를 지금 보는 화면들의 값을 같은 `args` 로 구한다. 숫자인 것 가운데 가장 짧은 것을 쓴다.
3. 숫자가 하나도 없으면 주기로 받지 않는다. 그 `args` 는 `refetch` · `Cache` 호출(`invalidate` · `fetch` · `setData`) ·
   event 로만 새로워진다. 0.1.0 의 자원은 모두 이 상태다.

### 10.3 타이머

- **`args` 하나에 타이머 하나.** 화면 하나에 하나가 아니다. 그 `args` 를 보는 화면(하나 꼴이든 목록 꼴이든)이 하나라도 있는
  동안만 돈다. 화면이 열리고 닫히거나 목록이 바뀌면 10.2 를 다시 구한다.
- **간격은 받기가 끝난 때부터 센다.** 받기가 끝나면 그때부터 간격 뒤에 다음 받기를 건다. 요청이 겹치거나 쌓이지 않는다.
- **창이 가려지면 멈춘다**(`document.visibilityState === "hidden"`). 다시 보일 때 간격이 이미 지났으면 곧바로 한 번 받고 다시
  건다.
- **실패하면 늦춘다.** 실패할 때마다 간격을 두 배로, 기본 간격의 8배까지 늘린다. 주기 받기 · `refetch` · `invalidate` 가운데
  무엇으로든 한 번 성공하면 기본 간격으로 되돌린다. 늘린 정도는 `args` 마다 따로 쥐고, 화면이 바뀌어 기본 간격이 바뀌어도
  늘린 정도는 그대로 두고 새 기본 간격에 곱한다. 창이 가려졌다 보여도 늘린 정도는 그대로다.
- **서버에서 그릴 때(SSR)는 타이머를 걸지 않는다.**
- `auto: false` 인 자원도 간격이 정해진 `args` 는 주기로 받는다. `auto` 는 「처음 볼 때 저절로 받을지」만 정한다.

## 11. 자리 채우기 — `placeholderData`

### 11.1 꼴

```ts
type Prev<A, D> = { args: A; data: D };

type PlaceholderData<A, D> =
  | D                                                    // 지어낸 값 그대로
  | ((args: A, prev: Prev<A, D>[]) => D | undefined);   // undefined: 정하지 않았다

createResource(define, { placeholderData?: PlaceholderData<A, D> });
useStore(key, { args, placeholderData?: PlaceholderData<A, D> });
```

- **`prev` 는 늘 배열이다.** 자원에 적은 함수 하나가 하나 꼴과 목록 꼴 모두에서 불리기 때문이다.
  - 하나 꼴: 이 화면이 바로 전에 보이던 `args` 와 그 값. 길이 0 또는 1.
  - 목록 꼴: 이 화면이 바로 전 렌더에 보이던 목록 전체. 항목마다 같은 배열이 온다. 무엇을 같은 자리로 볼지는 함수가 이 배열을
    보고 고른다.
- **언제 쓰이는가:** 그 `args` 에 받은 값이 없을 때다. 받는 중일 때와, 받다가 실패했을 때 모두다. 실패는 `status` · `error` 로만
  알리고 보이는 값에는 영향을 주지 않는다.
- **차례:** 자원의 것을 먼저 구한다. `undefined` 면 화면의 것을 구한다. 둘 다 없으면 `data` 는 `undefined` 다.
- **화면끼리는 서로 영향이 없다.** 자리를 채운 값은 그 화면에만 보이고, 받은 값은 모든 화면이 나눠 갖는다.
- `QueryView` 에 `isPlaceholderData: boolean` 을 더한다. 보이는 `data` 가 받은 값이 아니라 자리를 채운 값이면 `true` 다.

### 11.2 `keepPreviousData` 의 두 꼴

```ts
placeholderData: keepPreviousData                                              // 꼴 1
placeholderData: keepPreviousData((args, prev) => prev.args.repo === args.repo) // 꼴 2
```

| 꼴 | 하나 꼴에서 | 목록 꼴에서 |
|---|---|---|
| 꼴 1(그대로 넘긴다) | 바로 전 값을 잇는다. `args` 가 무엇으로 바뀌든 잇는다 | 같은 `args` 의 앞 값만 잇는다. 새로 들어선 항목과 `args` 가 바뀐 항목은 `undefined`. 옆 항목의 값이 밀려오지 않는다 |
| 꼴 2(`match` 를 넘긴다) | `match` 가 참이면 잇는다 | `prev` 가운데 `match` 가 참인 첫 항목의 값을 잇는다 |

```
목록 꼴 1:
전 args:      [ 뿌리,  src,  docs ]
지금 args:     [ 뿌리,  src,  src/components,  docs ]
맞춘 prev:     [ 뿌리,  src,  undefined,       docs ]
```

## 12. 바꾸어 꺼내기 — `select`, 그리고 `pick` 고치기

### 12.1 꼴

```ts
createResource(define, { select?: (data: D, args: A) => S1 });
useStore(key, { args, select?: (data: S1, args: A) => S2 });
```

- **자원의 `select`:** 캐시(`getData` · `setData` · `fetch` · 다른 store)는 서버 모양 그대로 두고, 화면에 줄 때만 바꾼다. `query`
  안에서 바꾸면 캐시에 바꾼 값이 앉는 것과 다르다.
- **화면의 `select` 는 자원의 결과를 이어 받는다.** 갈음하지 않는다. 자원이 화면용 모양으로 바꾸고, 화면은 그 모양에서 필요한
  조각을 꺼낸다.
- 자리를 채운 값에도 `select` 를 거친다(`placeholderData` 는 `D` 모양이다).
- 목록 꼴에서는 항목마다 불린다.

### 12.2 다시 그리기 — 겉 한 겹 견주기

자원 훅이 화면에 줄 값을 이 차례로 만든다.

1. 그 `args` 의 `{ data, status, error }` 를 꺼낸다. 받은 값이 없으면 11장의 자리 채우기를 한다.
2. `select` 를 자원의 것, 화면의 것 차례로 거친다.
3. `pick` · `omit` 으로 고른 칸만 남긴다.
4. 바로 전에 준 결과와 칸마다 `Object.is` 로 견준다. `data` 가 객체면 그 겉 한 겹의 칸도 `Object.is` 로 견준다. 모두 같으면 앞
   결과를 그대로 주어 다시 그리지 않는다.

- 깊이 견주지 않는다. `select` 가 배열을 그대로 돌려주면 새 응답마다 새 배열이라 다시 그린다. 필요한 값만 꺼내 돌려주도록 README
  에 적는다.
- 목록 꼴: 항목마다 견준다. 바뀌지 않은 항목은 앞 객체를 그대로 담고, 어느 항목도 바뀌지 않으면 앞 배열을 그대로 준다. 그래서
  `memo` 로 감싼 항목 컴포넌트는 바뀐 항목만 다시 그린다.

### 12.3 0.1.0 의 결함: 자원의 `pick`

0.1.0 의 자원 훅은 `pick` 과 상관없이 `{ data, status, error }` 전체를 구독하고 `pick` 은 돌려줄 칸만 거른다
(`src/query.ts` 의 `useResource`). 그래서 `pick: ["data"]` 를 주어도 다시 받기 시작해 `status` 가 바뀌면 다시 그린다. README
의 「pick 으로 고른 칸이 바뀔 때만 다시 그린다」가 자원에서는 거짓이다. 12.2 의 차례가 이것을 함께 고친다. 보통 store 의 `pick`
이 쓰는 「앞 결과 쥐기」(`src/react.ts` 의 `snapshot`)와 같은 꼴이다.

## 13. 바깥 엔진은 0.3 이 맡는다

0.2 에서 바깥 연결(웹소켓 · 프로세스 · 언어 서버)을 감싸는 꼴은 지금 그대로다. creator 안에서 엔진을 만들고 `subscribe` 해
`set` 한다.

```ts
createStore("infra.terminal", (set) => {
  const engine = createTerminalEngine("/ws/terminal");
  engine.subscribe(() => set({ sessions: engine.getSnapshot() }));
  return { sessions: engine.getSnapshot(), open: (cwd: string) => engine.open(cwd) };
});
```

이 꼴은 제품 빌드에서는 문제가 없다. store 를 다시 짓지 않기 때문이다. 개발 모드의 다시 등록과 시험의 `overrideStore` ·
`resetStores` 로 다시 지을 때만 앞 엔진이 닫히지 않고 남는다. 이것과 연결의 약속 · 서버 도우미는 0.3 의 `createStream` 이 푼다.
editor 는 엔진 셋을 이 꼴로 먼저 옮기고, 0.3 이 나오면 바꿔 끼운다.

## 14. 깨지는 것과 판 번호

- **`mutate` 가 아무것도 돌려주지 않는다.** 0.1.0 에서 `await save.mutate(…)` 의 결과를 받아 쓰던 자리는 `mutateAsync` 로 바꾼다.
  fortuna 에 2곳이 있다(`apps/web/src/app/(home)/GeneratorCard/GeneratorCard.presenter.ts:65`,
  `apps/web/src/app/(home)/HypothesisLab/HypothesisLab.presenter.ts:22`).
- **`args` 를 배열로 지은 자원**은 생성기가 실패시킨다. 0.1.0 을 쓰는 저장소에는 지금 없다.
- `QueryView` 에 칸이 둘(`isPlaceholderData` · `isFetching`) 는다. 칸을 펼쳐 쓰는 코드는 영향이 없다. 두 이름은 바꾸기 이름으로
  쓸 수 없다.
- **값이 있는 `args` 를 다시 받는 동안 `status` 가 `loading` 으로 바뀌지 않는다**(§16 19번). 0.1.0 에서 `refetch` · `invalidate`
  뒤에 `status === "loading"` 을 기다리던 코드는 `isFetching` 을 본다.
- 판 번호는 `0.2.0` 이다. 0.x 에서 둘째 자리를 올리는 것은 깨지는 바뀜을 담을 수 있다.
- 0.1.0 은 아직 npm 에 나가지 않았다(사람의 npm 계정 복구를 기다린다). 0.2.0 이 먼저 준비되면 0.1.0 을 건너뛰고 0.2.0 만 낼지
  사람이 정한다.

- **훅 시험(vitest):** 8 · 9 · 10 · 11 · 12 장의 규칙마다 하나 이상. 특히 아래는 이름을 붙여 둔다.
  - 같은 `args` 를 하나 꼴 화면과 목록 꼴 화면이 함께 보면 요청과 타이머가 하나다.
  - 목록에 항목이 끼어들어도 꼴 1 `keepPreviousData` 가 옆 항목 값을 밀어 넣지 않는다.
  - 새 `args` 가 실패해도 자리를 채운 값이 남고 `status` 가 `error` 다.
  - `pick: ["data"]` 화면은 `status` 만 바뀔 때 다시 그리지 않는다(12.3 의 결함을 다시 내지 않는다).
  - `select` 결과의 겉 칸이 같으면 다시 그리지 않는다.
  - 늦게 온 응답이 칸을 덮지 않는데 `mutateAsync` 는 자기 결과를 돌려준다.
  - 실패가 이어지면 간격이 두 배씩 늘고 8배에서 멈추며, 한 번 성공하면 되돌아간다.
  - 창이 가려지면 타이머가 멈추고, 보이면 간격이 지났을 때 곧바로 받는다.

  의 돌려주는 타입에 `undefined` 가 없음.
- **생성기 시험(node):** 배열 · 튜플 `args` 를 가진 정의가 §8.3 의 문구로 실패한다.

## 16. Claude 가 정한 것 — 사람이 확인할 것

1. **`fetch` 목록에서 하나가 실패하면 그 오류로 거절한다**(`Promise.all` 꼴). 하나 꼴의 `fetch` 가 실패하면 던지는 것과 맞췄다.
   항목마다 성공 · 실패가 필요하면 쓰는 쪽이 하나 꼴을 `Promise.allSettled` 로 묶는다.
2. **`setData` 목록의 updater 는 `(prev, args)` 를 받는다.** `args` 마다 다른 값을 넣을 수 있게 하려는 것이다. 하나 꼴의
   updater 도 둘째 인자로 `args` 를 받는다(0.1.0 코드는 첫 인자만 쓰므로 그대로 돈다).
3. **`invalidate([])` 는 아무것도 하지 않는다.** `invalidate()` 의 「모두」와 갈라, 빈 목록이 「모두」로 읽히지 않게 했다.
4. **하나 꼴과 목록 꼴이 같은 훅을 같은 차례로 부른다.** 한 자리에서 렌더마다 두 꼴을 오가도 React 의 훅 규칙에 걸리지 않게
   하려는 것이다.
5. **자리 채운 값도 `select` 를 거친다.**
6. **`auto: false` 자원도 간격이 정해진 `args` 는 주기로 받는다.**
7. **서버에서 그릴 때 타이머를 걸지 않는다.**
8. **`isPlaceholderData` 라는 칸 이름.** React Query 와 같은 이름이라 옮겨 오는 사람이 바로 읽는다.
9. **자원의 `select` 는 제네릭 자리를 하나 더한다.** `createResource<A, D, R, S = D>` 로, `S` 는 `options.select` 의 돌려주는
   타입에서 추론한다. `Cache` 는 `D`, 화면의 `data` 는 `S`(화면 `select` 가 있으면 그 결과)다. 생성 파일의 상태 타입에도 `S` 가
   실린다.
10. **`prev` 에는 그 화면이 실제로 보이던 값이 든다.** 받은 값이든 자리를 채운 값이든, 보이던 `data` 가 `undefined` 가 아니면
    든다. `undefined` 였던 항목은 들지 않는다. 그래서 `args` 를 A → B → C 로 빠르게 바꾸고 B 가 오기 전에 C 로 갔으면, C 는 B 자리에
    보이던 A 의 값을 잇는다. `Prev.data` 는 `select` 를 거치기 전의 `D` 다.
11. **실패하면 늦추기는 그 `args` 의 받기가 실패할 때마다 센다.** 주기 받기 · `refetch` · `invalidate` · 처음 받기 모두다. 되돌리기도
    무엇으로든 한 번 성공하면이다.
12. **타이머의 시작점.** 그 `args` 가 받는 중이면 받기가 끝난 때부터 센다. 받는 중이 아니면 타이머를 걸 때부터 센다. `auto: false`
    로 아직 받은 적 없는 `args` 는 간격 뒤 첫 주기 받기에서 처음 받는다.
13. **`mutate` 는 안에서 거절을 삼킨다.** 처리되지 않은 거절로 새지 않는다. 뒤 요청에 밀린 호출이 칸을 건드리지 않는 것은 0.1.0
    그대로다.
14. **생성기의 배열 `args` 검사는 `createResource` 호출의 `query` 첫 인자 타입을 본다.** 정의 파일 안의 모든 `createResource`
    호출이 대상이다(감싸여 있어도). 타입이 배열 · 튜플이거나 그것을 낀 유니온(`string[] | undefined`)이면 실패한다. `query` 를
    찾지 못하거나 타입을 읽지 못하면 건너뛴다.
15. **빈 목록.** `useStore(key, { args: [] })` 는 `[]` 를 돌려주고 아무것도 받지 않는다. `getData([])` · `fetch([])` 는 `[]` 다.
    `invalidate([])` 는 3번대로 아무것도 하지 않는다.
16. **옵션 함수가 렌더마다 새 함수여도 된다.** 자원 훅은 받은 값과 그때 쓴 함수가 바로 전과 같으면 앞 결과를 그대로 쓰고,
    다르면 렌더당 한 번 다시 구한다. 쓰는 쪽에 `useCallback` 을 요구하지 않는다. 효과 안에서 읽는 옵션(`refetchInterval`)만
    마지막 값을 ref 로 쥔다(2026-10-26 사람이 문구를 고쳤다 — 처음에는 「마지막 옵션을 ref 로 쥔다」였다).
17. **목록 항목의 같음은 0.1.0 과 같은 `args` 의 `JSON.stringify` 로 가른다.** 같은 `args` 가 목록에 두 번 들면 결과에도 두 번
    나온다. 구독 · 타이머 · 보는 화면 수는 한 번으로 센다.
18. **서버에서 그릴 때의 판정.** 타이머와 받기는 effect 안에서만 건다. 그래서 서버 렌더에서는 저절로 걸리지 않는다. 서버
    렌더 중 받기도 0.1.0 처럼 하지 않는다.

### 16.1 구현 뒤 사람이 정한 것 (2026-10-26)

19. **값이 있는 `args` 를 다시 받는 동안 `status` 는 그대로다.** 주기 받기 · `refetch` · `invalidate` 모두다. `ready` 는 `ready`
    로, 실패한 뒤라면 `error` 로 남는다. `loading` 은 그 `args` 에 받은 값이 없을 때(처음 받기, 비운 뒤 받기)뿐이다.
    「다시 받는 중」은 `QueryView` 의 새 칸 `isFetching: boolean` 이 알린다. 처음 받을 때도 `true` 다. `isFetching` 은
    `isPlaceholderData` 처럼 바꾸기 이름으로 쓸 수 없다. 0.1.0 의 `refetch` · `invalidate` 동작이 바뀐다(§14). React Query v5 의
    `status` · `isFetching` 과 같은 나눔이다.
20. **받는 동안에는 처음 채운 값을 쥔다.** 그 `args` 가 아직 받는 중이고 화면의 `placeholderData` 가 같은 함수면, 처음 채운 값을
    다시 구하지 않는다. 그래서 `keepPreviousData(match)` 로 잇는 원래 항목이 그사이 새 값을 받아도, 받는 중인 항목은 처음 채운
    값을 보인다. 받기가 끝나면 진짜 값으로 바뀐다. 부를 때마다 새 객체를 짓는 함수가 끝없이 다시 그리지 않게 하려는 것이고,
    React Query v5 와 같다.
21. **값 꼴 `setData` 도 `undefined` 를 받는다.** `setData(undefined, args)` 는 updater 꼴의 `() => undefined` 와 같이 그 `args` 를
    비워 idle 로 되돌린다. 낙관적 갱신에서 `cache.setData(prev)` 로 되돌리는 꼴(§7)이 그대로 맞는다.

## 17. 빌더에게 맡기는 것

- `Resource` 의 `[USE]` 를 서명 하나의 제네릭으로 지어, `useStore` 의 첫 갈래(`Parameters<UseFn<K>>` · `ReturnType<UseFn<K>>`)가
  하나 꼴과 목록 꼴을 모두 옮기게 하는 타입 짓기. 겹친 서명(overload)은 `Parameters` · `ReturnType` 이 마지막 것만 읽어 쓸 수
  없다.
- 타이머 · 늘린 정도 · 보는 화면 수를 `args` 마다 쥘 자료 구조. 0.1.0 의 `Cell` 에 더할지 따로 둘지.
- 목록 꼴에서 `args` 배열이 렌더마다 새 배열이어도(`map` 으로 만든다) 효과가 렌더마다 다시 돌지 않게 하는 견주기(칸 id 를
  이은 글자로 견주는 등).
- README 의 새 절: 「React Query 에서 옮겨 올 때」(§7 의 꼴과 §6 의 대응표), 여러 `args`, 주기, 자리 채우기, 바꾸어 꺼내기,
  `mutateAsync`.

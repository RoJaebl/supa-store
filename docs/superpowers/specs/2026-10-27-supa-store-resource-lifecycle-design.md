# supa-store — 자원이 보지 않는 값을 다루는 법 (짧은 설계)

- 날짜: 2026-10-27
- 상태: **승인됨(2026-10-27, 사람이 editor 이관 세션에서 「좋아. 설계를 승인할께」)**
- 계기: editor 의 React Query 이관에서 찾은 `createResource` 의 빈자리 셋. 근거와 editor 의 실제 자리는 공유 노트
  `supa-store-resource-gaps.md`(editor 이관 세션이 썼다).

## 의도와 까닭

args 가 많은 서버 값을 오래 쥐는 앱(파일 내용 · 폴더 목록 · 커밋 상세처럼 args 마다 값이 따로인 것)은 화면이 지금 보지 않는
args 의 값을 어떻게 다루는지에 부딪힌다. 지금 `createResource` 는 그것을 화면이 보는 값과 똑같이 다룬다.

- `invalidate()` 가 idle 이 아닌 모든 칸을 곧바로 다시 받는다(`src/query.ts` 의 `invalidate` · `reload`). 탭 셋을 거쳐 온 뒤 무효화하면
  요청이 셋 나가고, `await invalidate()` 도 셋을 다 기다린다.
- 어떤 args 를 무효화할지 조건으로 고를 길이 없다. 없음 · args 하나 · args 배열만 받는다.
- 보는 화면이 없어져도 칸을 지우지 않는다(`cells` 에서 지우는 자리가 없다). 서버가 알리지 않는 값은 다시 열어도 옛 값이고, 값이 메모리에
  쌓인다.

supa-store 는 화면이 지금 보는 args 를 이미 장부로 쥔다(`src/refetch.ts` 의 `watched`, `watch(args, screen)` 이 화면마다 더하고 뺀다).
셋 모두 이 장부로 메운다. 이것은 editor 의 키 모양이 아니라 supa-store 의 모델(args 마다 칸 하나, 화면이 args 로 고른다)에서 나오는 빈자리다.

## 정한 것 (제안)

### 1. 무효화는 보는 칸만 곧바로 다시 받는다

- `invalidate(...)` 가 고른 칸 가운데 **화면이 보고 있는 칸**(`watched` 에 있는 args)은 지금처럼 곧바로 다시 받는다.
- **보지 않는 칸**은 값을 그대로 두고 「낡음」 표시만 한다. 그 뒤
  - 화면이 그 args 를 다시 보면(`watch` 가 그 args 를 처음 더할 때) 곧바로 다시 받는다. 받는 동안은 앞 값을 보이고 `isFetching` 이 켜진다.
  - `fetch(args)` 가 그 칸을 부르면 쥔 값을 주지 않고 다시 받는다.
  - `getData(args)` 는 쥔 값을 그대로 준다(낡았어도).
- `await invalidate(...)` 는 곧바로 다시 받은 칸만 기다린다.
- 인자 없이, args 하나로, 배열로, 조건으로(2번) 고른 경우 모두 같은 규칙이다.

### 2. 조건으로 고른다

```ts
ctx("api.file.content").invalidate((a) => a.repo === "A");
```

- `invalidate` 가 `(args: A) => boolean` 도 받는다. 쥔 칸(idle 이 아닌 칸) 마다 불러 참인 칸을 고른다.
- args 자체가 함수인 자원과 헷갈리지 않게, 생성기가 query 의 args 를 함수 타입으로 짓지 못하게 막는다(배열 타입을 막는 것과 같은
  자리, 같은 꼴의 오류).
- `getData` · `setData` · `fetch` 에는 조건 꼴을 더하지 않는다(쓰임이 나오면 그때).

### 3. 보지 않게 된 칸을 놓는다

```ts
createResource(define, { release: 0 })        // 마지막 화면이 빠지면 곧바로 놓는다
createResource(define, { release: 5 * 60_000 }) // 5분 뒤 놓는다
createResource(define)                        // 생략하면 놓지 않는다(지금 동작)
```

- `release?: number | false`. 그 args 를 보던 마지막 화면이 빠지고 이만큼 지나면 그 칸을 `cells` 에서 지운다. 그사이 화면이 다시 보면 놓지 않는다.
- 놓을 때 진행 중인 요청의 응답은 버린다(칸이 없으므로 쓰지 않는다). 놓은 뒤 화면이 다시 보면 처음부터 받는다(`loading`).
- 기본은 놓지 않는다. 지금 쓰는 쪽(fortuna)의 동작이 바뀌지 않게 하려는 것이다. editor 는 놓아야 하는 자원(파일 내용 · 세션 기록)에
  `release: 0` 을 적고, 일부러 쥐는 자원(폴더 단계 · 드라이브)은 적지 않는다.
- 화면이 아닌 쪽의 읽기(`ctx` 의 `getData` · `fetch`)는 「보는 것」으로 세지 않는다. `fetch` 로 받은 칸도 화면이 보지 않으면 `release`
  대로 놓인다(마지막 화면이 빠진 때가 없으므로, 받은 때부터 센다).

## 고려한 길

| 길 | 이 길이 막는 것 | 고른 까닭 또는 버린 까닭 |
|---|---|---|
| 셋을 `watched` 장부로 메운다 | 셋 모두 | **골랐다.** 장부가 이미 있고, 화면이 args 로 고르는 모델에서 나오는 빈자리라 그 모델로 메운다 |
| React Query 의 `staleTime` · `gcTime` 을 그대로 들인다 | 셋 모두 | 버렸다. 시간 둘과 「낡음」 상태 표가 따라와 supa-store 의 「무효화하면 다시 받는다」 모델보다 커진다 |
| 0.3 `createStream` 으로 옮긴다 | 서버가 알리지 않는 값의 낡음 | 버렸다. store key 하나에 값 하나라 args 마다 값이 따로인 자원을 담지 못한다 |

## 하지 않는 것

- 「낡음」을 화면이 보는 칸(`isStale` 같은 것)으로 내보이기. 쓰임이 나오면 그때.
- `release` 의 기본값 바꾸기. 기본을 놓기로 바꾸는 것은 따로 정한다.

## Claude 가 정한 것 — 사람이 확인할 것

1. 옵션 이름은 `release`(놓는다)다. 값은 마지막 화면이 빠진 뒤 기다리는 ms, `false` 또는 생략은 놓지 않는다.
2. 기본은 놓지 않는다(지금 동작 그대로).
3. 1번의 규칙(보는 칸만 곧바로)은 옵션 없이 모든 자원에 걸린다. 지금 동작에서 바뀌는 것은 「보지 않는 칸을 곧바로 다시 받던 것」뿐이고,
   그 칸은 다시 볼 때 받는다.
4. 조건 꼴은 `invalidate` 에만 둔다.
5. 생성기는 함수 타입 args 를 막는다.

## 시험

- 탭 a · b · c 를 차례로 보고 c 만 남긴 뒤 `invalidate()`: 요청은 c 하나, `await` 는 c 만 기다린다. b 를 다시 보면 그때 받는다.
- `invalidate((a) => a.repo === "A")`: A 의 칸만 고른다(보는 것은 곧바로, 보지 않는 것은 낡음).
- 낡은 칸의 `fetch` 는 다시 받고, `getData` 는 쥔 값을 준다.
- `release: 0`: 마지막 화면이 빠지면 칸이 사라지고, 진행 중 응답은 버려지며, 다시 보면 `loading` 부터. 한 화면이 빠지고 다른 화면이 같은
  args 를 보면 놓지 않는다. `release` 를 주지 않으면 지금처럼 쥔다.
- 생성기: query 의 args 가 함수 타입이면 오류.
- fortuna 의 쓰임(옵션 없음)이 바뀌지 않는다: 기존 시험 전부 통과.

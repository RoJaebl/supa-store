# supa-store 0.3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 서버와 실시간으로 이어진 연결을 `createStream` 으로 store 에 꺼내고, 그 약속을 지키는 서버 도우미 `createStreamServer` 를 Node `http` · Web 표준 두 진입점으로 낸다.

**Architecture:** 약속(메시지 갈래 · 버전 · 기록 · 답 기록 · heartbeat · 닫기)을 전송과 떼어 서버 쪽 한 벌(`src/server/core.ts`), 클라이언트 쪽 한 벌(`src/stream/client.ts`)로 짓는다. 전송(웹소켓 · SSE)은 그 위의 얇은 겉이다. 화면은 0.2 의 자원 훅과 같은 꼴(`[USE]` · `pick` · 앞 결과 쥐기 · `MutationView`)으로 꺼내고, store 를 다시 지을 때 새 표식 `[DISPOSE]` 로 연결을 닫는다.

**Tech Stack:** TypeScript 5.x, React 18/19, vitest(jsdom · node 환경), Node 22 의 전역 `WebSocket` · `fetch`, 선택 peer `ws`(Node 웹소켓 서버), Node `http`.

**Spec:** `docs/superpowers/specs/2026-10-25-supa-store-0.3-stream-design.md`

**실행 자리:** 0.2(`release-0.2+`)를 dev 에 병합한 뒤, dev 에서 갈라진 `release-0.3+` 워크트리(`C:/Users/hnpark/orca/workspaces/supa-store/release-0.3`)에서 한다.

## Global Constraints

- 버전 `0.3.0`. 화면 쪽 진입점(`.` · `/react` · `/query` · `/stream`)은 런타임 의존 0개다. `ws` 는 선택 peer(`>=8`)이고 개발 의존으로 들인다.
- 0.2 의 정의 파일과 화면 코드는 고치지 않고 돈다.
- 하위 경로 넷: `supa-store/stream`(`createStream`) · `supa-store/server`(`createStreamServer`) · `supa-store/server/node`(`attachStream`) · `supa-store/server/web`(`streamHandler`).
- 메시지 갈래는 스펙 §7.1 표 그대로(`t`: `welcome` · `snapshot` · `change` · `reply` · `fate` · `request` · `ping` · `close` / `hello` · `command` · `ask` · `answer` · `pong`).
- 기록 기본: 최근 1000 개 또는 5분 가운데 짧은 쪽. heartbeat: 서버 `ping` 25초, 클라이언트 60초 동안 아무것도 못 받으면 끊긴 것. 다시 잇기: 1초부터 두 배씩, 30초에서 멈춤, ±20% 흔듦, 이어지면 1초. 창이 가려져도 다시 잇는다. 명령 제한 시간 기본 30초. `hello` 를 10초 안에 받지 못하면 서버가 닫는다.
- 닫기 코드: 4001 「다시 오지 마라」(다시 잇지 않는다), 4000 「곧 다시 와라」(곧바로 다시 잇는다). SSE 는 `close` 메시지, 연결 때 401 · 403 은 4001 과 같다.
- 문구 그대로: `연결 끊김. 재시도 중..` · `연결 끊김. 명령 실패` · `연결 끊김. 알 수 없음` · `응답 지연`.
- 토큰을 주소의 쿼리에 싣지 않는다. 웹소켓은 `hello.auth`, SSE 와 `POST` 는 `Authorization` 헤더.
- 정의 파일은 서버에서도 평가된다. `src/stream/*` 는 `"use client"` 를 두지 않고 React 는 이름공간으로 가져온다.
- 문서 · 주석 · 커밋 메시지 · 시험 이름은 한국어. 커밋마다 `pnpm typecheck` 와 `pnpm test` 가 통과한다.

## Review Focus

1. 같은 탭에서 store 를 여러 번 다시 지어도(개발 중 저장) 서버 쪽에 남은 연결 수가 늘지 않는다. → Task 6 시험
2. 다시 잇는 사이에 앞 연결의 늦은 메시지(`change` · `reply`)가 새 연결의 상태를 고치지 않는다. → Task 5 시험
3. 서버가 다시 떠 `epoch` 가 바뀌면 낡은 버전을 버리고 `snapshot` 으로 다시 시작한다. 같은 버전 번호의 `change` 가 버려지지 않는다. → Task 5 시험
4. 명령의 `reply.version` 이 이미 지난 버전이면(다른 화면이 먼저 따라잡았다) 곧바로 끝난다. 영영 기다리지 않는다. → Task 5 시험
5. `snapshot(ctx)` 이 던지면 그 연결만 `close`(4000)로 닫히고 홉과 다른 연결은 산다. → Task 2 시험

- Produces (`core.ts`):
  ```ts
  export interface StreamServerOptions<V, C, Id> {
    authorize?: (ctx: AuthCtx) => Id | Promise<Id>;     // ctx.reject(reason) 로 거절
    channel?: (ctx: AuthCtx & { identity: Id }) => string; // 기본 hello.channel ?? "default"
    snapshot: (ctx: ConnCtx<Id>) => V;                    // 동기
    commands?: Record<string, (ctx: ConnCtx<Id>, ...args: any[]) => unknown>;
    history?: { count?: number; ms?: number };
  }
  export interface StreamServer<V, C, Id> {
    publish(channel: string, change: C): void;
    attach(conn: Conn): void;                       // 전송 겉이 연결 하나를 넘긴다
    handlePost(req: PostReq): Promise<PostRes>;      // SSE 의 command · ask · answer
    close(): void;
  }
  export interface Conn { send(m: ServerMessage): void; close(code: number, reason: string): void; onMessage(fn: (m: ClientMessage) => void): void; onClose(fn: () => void): void; kind: "ws" | "sse"; headers: Record<string, string | undefined>; }
  export function createStreamServer<V, C = V, Id = unknown>(o: StreamServerOptions<V, C, Id>): StreamServer<V, C, Id>;
  // ConnCtx: identity, channel, token, connection, request(method, params): Promise<unknown>
  ```

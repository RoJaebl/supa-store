# supa-store 0.5 — 바꾸기 상태 · select 참조 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 자원이 바꾸기마다 상태(`inflight` · `pending` · `error` · `data`)를 쥐고, 자원 `select` 가 `ctx` 로 읽은 바꾸기 상태가
바뀌면 `select` 만 다시 돌게 한다. 결과 콜백 · `scope` 줄 · `ctx()` 를 함께 더한다.

**Architecture:** 바꾸기 하나를 새 모듈 `src/mutation.ts` 가 감싼다. 감싼 함수는 지금처럼 부를 수 있고, 상태 칸을 읽기 전용
속성으로 단다. 속성을 읽는 순간 같은 모듈의 「읽기 기록」에 그 바꾸기를 적는다. 화면 훅은 자원 `select` 를 그 기록 안에서
돌리고, 적힌 바꾸기를 구독하며, 그 version 을 건너뛰기 조건에 넣는다.

**Tech Stack:** TypeScript · React 18/19 `useSyncExternalStore` · vitest · @testing-library/react

**Spec:** `docs/superpowers/specs/2026-10-30-supa-store-mutation-state-design.md` (승인됨, 57f9684)

## Global Constraints

- 판 번호 `0.5.0`. 새 의존성을 들이지 않는다.
- 겉 이름: `inflight` · `pending` · `error` · `data` · `reset` · `onSuccess` · `onError` · `onSettled` · `scope: { id }`. 콜백과 `scope`
  는 `createResource` 옵션에 **바꾸기 이름을 열쇠로** 적는다.
- 오류 문구 그대로: `짓는 동안에는 자기 자신을 꺼낼 수 없다: <key>`.
- 호출 번호는 겉(타입 · 화면)에 드러나지 않는다.
- 호출 하나의 차례: `inflight` 에 넣기 → (`scope` 면 줄 차례 기다림) → 함수 → 늦음 견주기 → `data`/`error` 적기와 콜백 → **그 뒤**
  `inflight` 에서 빼기.
- 늦은 응답(같은 바꾸기에서 더 나중에 보낸 호출이 이미 끝났다)은 `data` · `error` 를 고치지 않고 세 콜백을 부르지 않는다. 그
  호출의 Promise 는 자기 결과로 끝난다.
- `reset()` 은 차례를 올린다. `inflight` 는 지우지 않는다.
- 콜백이 던지면 `console.error` 로 남기고 삼킨다.
- 정의 함수는 다시 짓지 않는다. 다시 도는 것은 `select` 뿐이다.
- 안쪽 `Cell.inflight`(진행 중 받기 Promise)는 `request` 로 이름을 바꾼다.
- 연결 명령(`src/stream/hook.ts`)은 지금의 화면별 `useMutation` 을 그대로 쓴다.
- 주석 · 시험 이름 · 커밋은 이 저장소처럼 한국어 평서문으로 적는다.

## Review Focus

1. **바꾸기가 날아가는 중에 화면이 처음 붙는다** — 첫 렌더부터 겹이 보여야 한다. (Task 5 시험)
2. **날아가는 중에 화면이 떨어졌다 다시 붙는다** — 상태는 자원에 있으므로 다시 붙은 화면이 `pending` 을 본다. (Task 4 시험)
3. **같은 인자로 두 번 동시에 부른다** — `inflight` 에 둘이 서고, 끝난 쪽 하나만 빠진다. (Task 2 시험)
4. **날아가는 중에 `resetStores` · Fast Refresh 로 자원이 다시 지어진다** — 옛 호출이 끝나도 던지지 않고, 새 자원의 `inflight` 는
   비어 있다. (Task 2 시험)
5. **`scope` 줄에서 앞 호출이 실패한다** — 다음 호출은 막히지 않고 나간다. (Task 3 시험)

- Produces (`src/mutation.ts`):

  type Fn = (...args: any[]) => any;
  /** 바꾸기 하나의 상태 — 바뀔 때마다 새 객체다 */
  export interface MutationSnapshot<F extends Fn> {
    readonly inflight: readonly Parameters<F>[];
    readonly pending: boolean;
    readonly error: string | null;
    readonly data: Awaited<ReturnType<F>> | undefined;
  }
  /** 부를 수 있는 바꾸기 — 상태 칸은 읽기 전용 속성 */
  export type MutationFn<F extends Fn> = F & MutationSnapshot<F> & { reset(): void };
  export interface MutationHooks<F extends Fn> {
    onSuccess?: (result: Awaited<ReturnType<F>>, ...args: Parameters<F>) => void;
    onError?: (error: unknown, ...args: Parameters<F>) => void;
    onSettled?: (result: Awaited<ReturnType<F>> | undefined, error: unknown, ...args: Parameters<F>) => void;
    scope?: { id: string };
  }
  /** 구독 단위 — 화면 훅과 읽기 기록이 쓴다 */
  export interface MutationChannel {
    subscribe(listener: () => void): () => void;
    snapshot(): MutationSnapshot<Fn>;
  }
  export function createMutation<F extends Fn>(fn: F, hooks?: MutationHooks<F>): { call: MutationFn<F>; channel: MutationChannel };
  ```

  }
  ```

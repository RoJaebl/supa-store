# supa-store 0.2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 자원이 여러 `args` · `mutateAsync` · `refetchInterval` · `placeholderData` · `select` 를 갖추고, 자원의 `pick` 이 고른 칸만 견주게 한다.

**Architecture:** `createResource` 정의와 `query` 서명은 그대로 두고, `Cache` 가 `args` 배열을 받게 넓힌다. 자원의 화면 훅을
`src/query.ts` 에서 `src/resourceHook.ts` 로 떼어 내고, 하나 꼴과 목록 꼴을 같은 훅 차례로 처리하며 「앞 결과 쥐기」로 다시 그리기를
줄인다. 주기 받기는 `args` 마다 타이머 하나를 쥐는 `src/refetch.ts` 가 맡는다.

**Tech Stack:** TypeScript 5.x, React 18/19(`useSyncExternalStore`), vitest + @testing-library/react(jsdom), node --test(생성기), TypeScript compiler API(`tools/codegen.cjs`).

**Spec:** `docs/superpowers/specs/2026-10-25-supa-store-0.2-design.md`

## Global Constraints

- 판 번호 `0.2.0`. 패키지 이름 `supa-store`, 라이선스 MIT.
- 런타임 의존 0개. peer: `typescript >=5.4`(필수), `react >=18` · `vite` · `next`(선택). 새 의존을 들이지 않는다.
- `createResource` 의 정의 함수와 `query` 서명은 바뀌지 않는다. 0.1.0 의 정의 파일은 고치지 않고 돈다.
- 정의 파일은 서버 쪽에서도 평가된다. `src/query.ts` 와 새 파일은 `"use client"` 를 두지 않고, React 는 이름공간(`import * as React from "react"`)으로 가져온다. 훅은 `[USE]` 안에서만 부른다.
- 문서 · 주석 · 커밋 메시지 · 시험 이름은 지금 코드처럼 한국어로 쓴다.
- 생성기 오류 문구는 그대로: `<파일>: 자원의 args 는 배열로 짓지 않는다 — 여러 값은 객체로 묶는다`
- 칸 이름 그대로: `mutateAsync`, `isPlaceholderData`, 옵션 `refetchInterval` · `placeholderData` · `select`, 도우미 `keepPreviousData`.
- 다시 그리기 견주기는 겉 한 겹(칸마다 `Object.is`, `data` 가 객체면 그 겉 칸도 `Object.is`)까지다. 깊이 견주지 않는다.
- 주기: `args` 하나에 타이머 하나 · 간격은 받기가 끝난 때부터 · 창이 가려지면 멈춤 · 실패하면 두 배씩 기본 간격의 8배까지 · 한 번 성공하면 되돌림.
- 커밋마다 `pnpm test` 가 통과한다(빌드 · vitest · node 시험).

## Review Focus

1. 화면이 `args` 를 렌더마다 `map` 으로 새로 만든다 — 효과가 렌더마다 다시 돌거나 요청이 되풀이되지 않아야 한다. → Task 4 시험
2. 주기 받기가 도는 중에 `overrideStore` · `resetStores` 로 자원을 다시 짓는다 — 앞 캐시의 타이머가 멈추고 새 자원에 다시 걸린다. → Task 7 시험
3. 받는 중에 화면이 떠난다 — 받기가 끝나도 다음 타이머가 걸리지 않는다. → Task 7 시험
4. 같은 `args` 가 목록에 두 번 든다 — 요청은 하나, 결과에는 두 번. → Task 4 시험
5. 자리를 채운 값에도 화면 · 자원의 `select` 가 걸린다 — `data` 의 모양이 받은 값과 같다. → Task 6 시험

  ```ts
    getData(args?: A): D | undefined;

  ```
  런타임은 `Array.isArray(args)` 로 목록을 가른다(Task 2 의 생성기 검사가 배열 `args` 를 막는 것이 전제).

- [ ] **Step 1: 실패하는 시험을 쓴다**

```ts
it("Cache 목록: getData 는 같은 순서의 배열을 준다", async () => {
  const r = createResource(() => ({ query: async ({ id }: { id: number }) => id * 10 }));
  await r.fetch({ id: 1 });
  expect(r.getData([{ id: 1 }, { id: 2 }])).toEqual([10, undefined]);
  expect(r.getData([])).toEqual([]);
});
it("Cache 목록: fetch 는 값 배열을 주고, 하나라도 실패하면 그 오류로 거절한다", async () => {
  const r = createResource(() => ({
    query: async ({ id }: { id: number }) => { if (id === 2) throw new Error("둘"); return id; },
  }));
  await expect(r.fetch([{ id: 1 }, { id: 3 }])).resolves.toEqual([1, 3]);
  await expect(r.fetch([{ id: 1 }, { id: 2 }])).rejects.toThrow("둘");
  await expect(r.fetch([])).resolves.toEqual([]);
});
it("Cache 목록: invalidate([a, b]) 는 그 둘만 다시 받고, invalidate([]) 는 아무것도 하지 않는다", async () => { /* query 를 vi.fn 으로 세고, 받아 둔 a·b·c 가운데 a·b 만 다시 불렸는지, [] 는 0번인지 */ });
it("Cache 목록: setData 의 updater 는 args 마다 (prev, args) 로 불린다", () => {
  const r = createResource(() => ({ query: async ({ id }: { id: number }) => id }));
  r.setData((prev, args) => args.id + 100, [{ id: 1 }, { id: 2 }]);
  expect(r.getData([{ id: 1 }, { id: 2 }])).toEqual([101, 102]);
});
```

타입 시험도 하나 둔다: `expectTypeOf(r.getData([{ id: 1 }])).toEqualTypeOf<(number | undefined)[]>()`, `expectTypeOf(r.fetch([{ id: 1 }])).toEqualTypeOf<Promise<number[]>>()`.

## Global Constraints

- 패키지 이름은 scope 없는 `supa-store`, 첫 판 `0.1.0`, 라이선스 MIT.
- 런타임 의존 0개. peer: `typescript >=5.4`(필수), `react >=18`·`vite`·`next`(선택).
- 런타임·자원·event·생성기의 동작은 바꾸지 않는다 — 바뀌는 것은 설계가 적은 넷(이름, `targets` 기본값, 문자열 아닌 key 실패, `references` 따라가기)뿐이다.
- `Symbol.for` 키: `"supa-store.use"` · `"supa-store/watching"` · `"supa-store/original"`. 판 번호를 넣지 않는다.
- 하위 경로: `.` · `/react` · `/query` · `/config` · `/vite` · `/next` · `/plugin`, bin `store-gen`. `./tools/plugin.cjs` 하위 경로는 없다.
- ESLint 규칙을 내지 않는다.
- git 은 `git-strategy` 스킬을 따른다 — 브랜치를 만들거나 병합·push 하기 전에 그 스킬을 부른다. 상시 브랜치 `main`·`dev`, 작업 브랜치 이름 끝에 `+`.
- `npm publish` 는 사람이 돌린다. 원격 저장소를 만드는 것과 push 는 사람 확인 뒤에 한다.
- 문서·주석·커밋 메시지는 이전 코드처럼 한국어로 쓴다.

## Review Focus

- Vite 감시자가 넘기는 경로가 Windows 역슬래시·대소문자 다른 드라이브 글자여도 `config.match` 가 맞혀야 한다 — Task 4 시험이 역슬래시 경로로 확인한다.
- Vite `root` 가 프로젝트 뿌리가 아닌 하위 폴더(`src/`)여도 `package.json` 을 거슬러 찾아 생성해야 한다 — Task 4.
- 개발 중 정의 파일의 문법이 깨지면 서버는 살아 있고, 고치면 다음 변경에서 다시 생성해야 한다 — Task 4.
- 뿌리 tsconfig 의 `references` 가 파일(`./tsconfig.app.json`)을 가리키든 폴더를 가리키든, 정의 파일이 든 설정이 없든 동작해야 한다 — Task 3.
- 템플릿 리터럴 key(`` createStore(`x`, …) ``)도 「문자열 그대로」가 아니므로 실패해야 한다 — Task 3.
